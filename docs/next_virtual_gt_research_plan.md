## 1. 先给结论

**下一步只新增一个生成模块：分别生成两盏灯的正照明贡献图，由它们算出混光比例、总明暗和虚拟白点。先用两个匹配训练，区分“换空间分布”的收益和“增加明暗变化”的收益。**

不再把状态轮换、共享 crop、精细 q/tau、困难 patch、新 loss、三光源和深度一起排进第一批。原有在线增强不是问题本身；同一来源本来可以重复接受不同照明。配对编排可以作为后续小实验，但没有足够证据将其作为这次突破的前提。

双高斯是计算便宜、参数直观的候选，不是已经证明更好的答案。它的价值在于可以直接控制照明位置、范围、方向和相对强弱，并清楚分离颜色与强度。随机场也不是数学上不自洽；二者主要区别是采用了不同的空间分布先验。

## 4. 生成器用白话怎么工作

取同一张允许的单光源来源图，按父项路径得到白平衡底图。它仍含原始明暗，并不是恢复出的光谱反射率。

先抽两个允许的 Nikon train 光源颜色。给每个光源抽一个光斑中心、一组照射范围、一个方向和相对强度。每盏灯产生一张“中心较强、向外衰减”的正贡献图。

然后对每个像素做两件事：

- 两盏灯贡献之比，决定这里偏哪种光源色。
- 两盏灯贡献之和，决定新增照明有多强。

贡献为 8 和 2，与贡献为 0.8 和 0.2，得到相同的白点方向，但总强度不同。权重来自人为生成的照明贡献，不从原照片亮度猜测；黑色物体较暗不等于受到的照明弱。

它比旧 M 更直观，但并非完整渲染：二维中心是光斑中心，不是真实三维灯具坐标；高斯不是点光源的距离平方反比规律；没有表面法线、遮挡、反射间接光。白平衡底图已有的 shading 仍保留，因此只能称“在对角 RGB 近似下自洽的合成监督”。

## 5. 交给实现者的数学定义

### 5.1 约定

使用父项相同的线性 RGB 输入、黑电平约定、有效 mask 与颜色顺序。两个端点先 G 归一化：`L_k=(r_k,1,b_k)`。训练图像来源只来自 official train 的 `_1.tiff` 与 Light1；沿用现有合法端点池、过滤与抽样方法。

设 `W = I_original / L_original` 为父项白平衡底图；不要改名为已知真实反射率。

### 5.2 两张高斯贡献图

```text
u_k(x) = a_k * exp(-0.5 * (x-c_k)^T * inverse(Sigma_k) * (x-c_k))
Sigma_k = R(theta_k) * diag(sigma_xk^2, sigma_yk^2) * R(theta_k)^T
```

`a_k>0`，`Sigma_k` 正定。这里使用峰值幅度形式，不是要求积分等于 1 的概率密度；不要把每张离屏光斑在画面内的最大值重新拉到 1，否则中心位置与强度的含义会变化。

下面是**本版建议的待校准起始配置，不是论文最优参数或真实场景统计拟合**。256×256 画面坐标均归一化到 `[0,1]`：

| 参数 | 起始抽样 |
|---|---|
| 每盏灯中心横、纵坐标 | 分别 `Uniform(-0.15, 1.15)`，允许少量中心在画外 |
| 每盏灯两个方向的 sigma | 分别 `LogUniform(0.35, 1.0)`，两灯独立 |
| 椭圆方向 | `Uniform(0, pi)` |
| 相对强度 | `b ~ Uniform(-ln(4), ln(4))`；`a_1=exp(b/2), a_2=exp(-b/2)` |
| 光源颜色 | 复用父项允许的 Nikon train 端点抽样，不额外筛选大色差配对 |

使用较宽光斑起步，是为了不把所有图都做成两个极小亮点，并不保证 alpha 过渡一定宽；还需记录实际 patch 内变化。以上范围不通过真实混光图或 GT 调整。正式运行前只用允许的 train 来源检查数值、形状与吞吐；任何修订先登记，再冻结，不边看 test 边改范围。

### 5.3 由贡献得到白点与总强度

```text
T(x)     = u_1(x) + u_2(x)
alpha(x) = u_1(x) / T(x)
F(x)     = u_1(x)*L_1 + u_2(x)*L_2
E(x)     = F(x) / T(x)
         = alpha(x)*L_1 + (1-alpha(x))*L_2
```

因为端点 G=1，`F_G=T`，所以 `E_G=1`。`E` 是虚拟光源色度图；`F` 是包含强度的三通道照明场。这里贡献尺度是与该相机/G 归一化约定一致的相对尺度，不是实测 lux 或灯具功率。

建议在 log 域生成贡献并稳定求比值，避免用很大的 epsilon 把暗区色度任意拉偏。记录全部数值非有限或下溢事件；不要把数值问题变成新标签。

### 5.4 同一组高斯参数生成两个训练版本

**DG-C：只改变空间混光比例。**

```text
J_color(x) = W(x) * E(x)
```

不新增明暗场，保留底图原有 shading。它测试高斯比值形成的空间先验，而不是完整双光强度模型。

**DG-CS：同样的 E，再保留受限总强度变化。**

```text
S_raw(x) = T(x) / median_x(T(x))
S(x)     = clip(S_raw(x), 0.25, 4.0)
J_color_intensity(x) = W(x) * S(x) * E(x)
```

中位数归一化只有一个整图标量，用于控制曝光尺度；对 S 的范围限制也是中性标量操作，RGB 使用同一个 S，不逐通道截断。`[0.25,4]` 是本版建议的保守增强范围，不是实测物理范围。记录 S 上下限触发比例。

**这里必须准确命名：DG-CS 是“高斯比值色度＋受限总强度”，不是未经处理的纯高斯辐射叠加。** 不限幅时它等于 `W*F/median(T)`；限幅后相当于给两个贡献同时乘上相同的逐像素倍率，二者比例与 E 不变。不能隐藏这个差别。

两组必须复用完全相同的来源、端点、高斯参数、crop、patch 坐标和 GT；差别只有 S 是否进入输入。原图分支一律不变。

### 5.5 标签顺序不能错

逐像素监督保存 `E=F/T`，沿用现行 One-Net 标签规则，对每个 patch 的 G=1 色度图 E 先取均值。不能换成先平均 F 再归一化，否则更亮像素会得到更高权重，两个实验的监督问题就不一样了。

角误差评估时的单位向量化遵循原 evaluator；不要在 patch 聚合前自行改成另一种逐像素单位范数约定。

DG-C 白平衡校正后的参考图是 W；DG-CS 用 E 校正后的参考图是 `W*S`，不是 W。AWB 去掉光源颜色，不应顺便把新生成的中性明暗全部移除。若展示视觉结果，必须使用这一对应关系，避免误判为标签不一致。

## 6. 一个容易忽略的数学限制

只用两个相同大小、相同形状的高斯，未必产生丰富的混光结构。由上式可推导：

```text
log(alpha/(1-alpha)) = log(u_1/u_2)
```

若 `Sigma_1=Sigma_2`，两个二次项相减时 `x^T inverse(Sigma) x` 抵消，右侧变成坐标 x 的仿射函数。于是 alpha 只是一个沿直线方向变化的 sigmoid 过渡。

这不是文献性能结论，而是本方案的代数性质。它解释了为什么“随机两个位置”本身不一定比已有 sigmoid 场丰富。因此本版让两灯的宽度、方向独立抽取，不强制相同尺寸；但也不预设越复杂越好。

圆形且不同宽度也能解除上述相同协方差退化；选择椭圆只是为了用很少参数覆盖更一般的方向和范围。原 M 仍是合法的对照，不因新场能解释为光斑就被判为无效。

## 7. 最小实验：两个新增训练，暂不改变状态安排

本批以**开发预选 O 的构造配置**为父项，不加载 O 的训练权重。保留 O 的在线样本安排、原图/mixed 实际消费方式、crop、patch 抽样和所有训练设置；只替换进入 mixed 分支时的空间场模块。

| 配置 | 混光比例从哪里来 | 新增明暗 | 用途 |
|---|---|---|---|
| O，既有参照 | 现有 M 随机场 | 无 | 当前参照，约 2.424 度 |
| DG-C，新训练 1 | 两张高斯贡献的比值 | 无 | 高斯空间分布是否帮助泛化 |
| DG-CS，新训练 2 | 与 DG-C 完全相同 | 同一对高斯产生的受限总强度 | 强度变化是否有额外收益 |

模型、损失、优化器、学习率日程、随机初始化协议、每源两个 view、每 view 64 个 patch、每步视图数以及 **69,600 次成功更新**均不变。新增随机数使用独立流，不扰动原图分支与采样清单。关闭新模块时必须复现父项路径；否则补跑匹配 O 控制，不能拿代码链路差异归因于高斯。

这一固定比例只是本次控制变量，并不否定每个 source 可以反复接受原始、人工单光源和人工多光源三种状态。三种状态接口保留；不在本次两个训练中同时增删人工 global 分支或改变其权重，也不强迫每次同时消费三张图。

先按原冻结开发规则比较 O、DG-C、DG-CS；精确同分保留改动更少者，顺序 O、DG-C、DG-CS。最终配置、checkpoint、所有开发子项先登记，再统一真实 val/test 评分。保留原有 18 格验收和后续 seed 授权条件，不根据 test 选择胜者或修改参数。

**不因 DG-CS 的数学形式更像照明叠加，就预设它一定比 DG-C 好。** W 已含原 shading，新增强度有可能扩大域差距。直接通过匹配对照决定是否值得保留。

## 8. 必须先完成的交付，而不是先跑大网格

### 8.1 原始数据与数值检查

核对生产路径是否已去黑电平、是否线性、RGB 顺序及 mask，且与父项一致。LSMI 官方 TIFF 转换步骤本身不去黑电平，后续处理步骤另做；这只构成审计理由，不能据此断言当前 Nikon runner 有 bug [R2]。

核对整图/patch 归一化维度，直接检查进入 One-Net 的张量。两个实验的 E、patch 标签、有效位置、原图分支必须匹配，明暗操作是否被预处理大体抵消也应报告。不能为了恢复某种信号悄悄改 normalization 后仍称只换了生成器。

### 8.2 生成器样例与分布检查

从允许 train 来源中事前固定 12 张代表样例，只用于实现验收。每张保存同一个 seed 的 W、u1、u2、alpha、E、S、DG-C 输入与 DG-CS 输入；GT 校正结果分别应对应 W 和 W*S。

无须生成固定几万张成品，但可以只生成 2,048 组低成本光场，用固定 seed 检查参数分布、alpha 均值/方差、局部主导区比例、16×16 内变化、S 限幅比例和有限性。不要依据真实混光 GT 或模型 test 误差筛选光场；不要专挑好看的图展示。

### 8.3 吞吐与训练检查

缓存坐标网格，批量计算两张指数图和逐像素加乘除；不增加深度网络、GAN 或 diffusion。算量随像素数线性增加，但是否在当前平台更快需要实测，不能把 O 的历史训练时间直接当作新配置承诺。

先做小批真实来源前向/反向检查和吞吐记录，确认 loss/梯度有限、参数有更新；正式训练重新加载冻结随机初始权重，校准更新不计入预算。本次文档更新不等于这些检查已完成，也不等于已授权启动。

## 9. 结果如何决定下一步

开发选型仍只依赖冻结的单光源与合成开发集；以下真实域指标的解释仅用于冻结后报告，不据 test 临时改本批计划。历史 test 已反复查看，不能宣称全流程盲测或统计显著优越。

- DG-C 若优于直接参照而 DG-CS 无额外收益：保留空间分布改动，不强行增加照明强度。
- DG-CS 若进一步改善：下一项候选是复用完全相同的一批 S 场、打乱它与 E 的配对，区分一般明暗变化与特定色度—强度关联。须另行事前冻结与授权，不能在看到 test 后无记录地加入。
- 两者均无有意义的收益：不继续在高斯宽度上反复刷 test。单个光斑只描述很平滑的投影场，下一类问题应是场景结构/可见性是否限制了泛化，而不是再换一组随机数。

内容相关支持的候选来自 Das 等的软分割构造思路 [R3]，但本项目不能直接把材质颜色边界等同于照明边界；先做有依据的小对照，再考虑深度/法线/遮挡。三光源、新 loss、困难采样和状态配对继续后置。

## 10. 什么是本工作的潜在贡献

“用高斯图合成多光源”“白平衡后随机重光照”“同一场景在线增强”均已有先例，本版不宣称首次提出。

值得争取的是：在不读取真实混光图、真实 mixture map、dense GT 或其派生信息来构造/训练/调参的条件下，证明一个简单的贡献场生成器能提供有效 dense supervision，并在固定模型、预算和评测下优于原真实监督训练。

两张高斯图只是第一版可控生成器。若没有真实泛化收益，不能靠“更符合物理”或“更有论文味道”代替证据。若有收益，再通过两个匹配对照说明来自何处，而不是把配对、loss、训练量与生成器一起改变。
